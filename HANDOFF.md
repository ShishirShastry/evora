## What works (Phase 1, then the Phase 2 additions)

All of this is wired to the real document model, is undoable, and is saved automatically.

- **Files.** File browser with create, open, rename, duplicate, delete (with confirmation) and import. Files are stored in the browser's IndexedDB on this device. "Save a copy to disk" writes a `.opendesign` file; importing reads one back. Files are validated and repaired on open; files from a newer format version are refused.
- **Autosave** about 0.4 s after each change, with an honest status in the toolbar (Saved / Unsaved changes / Saving… / Not saved). Reloading the page restores the file, the page you were on and the view.
- **Canvas.** Infinite canvas drawn by our own Canvas 2D renderer (no DOM elements per object), high-DPI, with culling of off-screen layers. Pan: wheel, Space + drag, middle button, hand tool. Zoom: Ctrl + wheel / pinch about the pointer, zoom in/out, fit, selection, 100 %, custom percentage.
- **Tools.** Move, Hand, Frame, Rectangle, Ellipse, Line, Polygon, Star, Text, Pen, Pencil. Drag to draw (Shift = square / 45° line, Alt = from centre) or click for a default size. Shapes drawn over a frame go inside it.
- **Selection.** Click, Shift-click, marquee, double-click to go deeper, Ctrl-click for the deepest layer, frame name labels, hover outline. Hidden and locked layers cannot be hit.
- **Transform.** Drag to move (Shift = one axis, Alt = duplicate, Escape = cancel); dropping on a frame nests the layer, dragging out un-nests it, keeping its place on the page. Eight resize handles (Shift = keep proportions, Alt = from centre), correct for rotated layers. Rotate by dragging outside a corner (Shift = 15° steps). Line endpoints. Multi-selection move, resize and rotate. Arrow-key nudge (Shift = 10).
- **Frames** with children in the frame's own coordinate space, optional clipping, corner radius.
- **Layers panel.** Tree of the current page; select, multi-select, rename, show/hide, lock/unlock, expand/collapse, drag to reorder and to nest, context menu. Only the rows in view are made, so the list costs the same however many layers a page has; selecting a layer on the canvas scrolls the list to its row.
- **Pages.** Add, switch, rename, duplicate, move up/down, delete.
- **Properties panel.** X, Y, W, H, rotation, corner radius, polygon points, star ratio, clip content, layer opacity, fills and strokes (colour, opacity, visibility, add/remove), stroke weight and position, page background. Multi-selection shows "Mixed".
- **Undo / redo** for every document change, one step per gesture, restoring selection and page.
- **Edit commands.** Cut, copy, paste, duplicate, delete, select all, bring to front / forward / backward / to back.
- **Groups (Phase 2).** Group (Ctrl+G) and ungroup (Ctrl+Shift+G, also dissolves frames). A group's box always fits its children; resizing a group scales its contents; an emptied group disappears. Click selects the group, double-click goes inside; a layer dragged about inside a group stays in it.
- **Arrange (Phase 2).** Align left / centre / right / top / middle / bottom (to the selection, or to the parent frame for a single layer), distribute horizontal and vertical spacing, flip horizontal and vertical. Available from the properties panel, the Arrange and Object menus and shortcuts. A flip gives the mirror image of what a layer is painted with too: a gradient changes sides, the radii of corners swap, the slice of an ellipse, the arrowheads of a line and the fall of a shadow are mirrored, inside frames and groups as well.
- **Text (Phase 2).** Text tool (T): click for text that grows with what you type, or drag out a box that wraps. Typed in place on the canvas in an editable element laid over the layer (the browser's own caret, selection and clipboard), at any zoom and rotation. Double-click or Enter edits existing text; Escape, Ctrl+Enter or clicking away finishes. Font family (Inter, which ships with the application and is what new text is set in, and the fonts installed on the machine), weight, size, line height, letter spacing, horizontal and vertical alignment, auto width / auto height / fixed size, letter case, underline or strikethrough, italic, fill colour. The layer resizes itself to its text and is named after it. Leaving new text empty creates nothing. Text can also be justified (wrapped lines reach both edges; the last line of a paragraph does not), and a layer can be a bulleted or a numbered list: every paragraph gets a bullet or its number and its lines are set in.
- **Bundled font (Phase 2).** The Inter typeface ships with the application, in nine weights, upright and italic, so text set in it looks the same on every machine; it is also the font of the application's own interface. The faces most text needs are fetched before a file is shown, so nothing is measured in a stand-in font; text in another script (Cyrillic, Greek, Vietnamese and so on) fetches its face when it first appears, and the layers set in it are then sized again. The font is under the SIL Open Font License 1.1: see `THIRD_PARTY_NOTICES.md`; its licence text is served with the application.
- **Styles on part of a text (Phase 2).** While a text is being edited, select part of it and the Text section of the properties panel (headed "Text (selected part)") shows and changes that part only: font, weight, size, letter spacing, underline or strikethrough, italic, and a colour of its own (with "Reset" to give it back to the layer's fill). The text stays open while the panel is used, with the selected part marked. Ctrl+B, Ctrl+I and Ctrl+U switch bold, italic and underline for the selected part, or for all of the text when nothing is selected. Characters typed in take the style of the character before them. A line is as tall as its largest text. With nothing selected, or when the layer is selected without editing it, a setting applies to the whole layer and replaces what its parts had for it; where parts differ the panel shows "Mixed". Ctrl+Z and Ctrl+Shift+Z undo and redo typing while the text is open.
- **Snapping (Phase 2).** While moving, resizing or drawing, edges and centre lines snap to the other layers in the same frame and to the frame's own edges and centre, within 6 screen pixels, and the lines snapped to are shown as guides. An axis locked with Shift is not snapped. "Snap to objects" in the View menu switches it off; the choice is remembered on this device. A layer being moved also snaps to even spacing with the layers in line with it: halfway between its two neighbours, or beyond a neighbour by the gap that neighbour has to the next one; whichever of a line and an even place is nearer wins. Whenever a moving layer sits in equal gaps, however it got there, the gaps are drawn with their sizes.
- **Distances (Phase 2).** With something selected, holding Alt shows the distances from the selection to the layer under the pointer: the gap between them where they are apart, and how far each edge is from the same edge of the other where they overlap. Over the selection itself, or over nothing, it measures to the frame the selection is in, which gives its distance from each side. Each distance is a line with its length in a label; it appears and goes as Alt is pressed and released, without moving the pointer.
- **Appearance (Phase 2).** Fills and strokes can be solid or a linear, radial, angular or diamond gradient with any number of colour stops (colour, position, opacity) and an angle. Strokes have flat / round / square ends, sharp / cut / round corners and dashes with a gap. Frames and rectangles can have a different radius on each corner. Effects: drop shadow and inner shadow (offset, blur, spread, colour, opacity), layer blur and background blur, stacked, each hideable. Sixteen blend modes. Opacity, blend mode, blur and shadow apply to a layer as a whole, children included.
- **Images (Phase 2).** Place PNG, JPEG, WebP, GIF or SVG files from File → Place image… (Ctrl+Shift+K), by dropping them on the canvas, or by pasting from the clipboard. An image becomes a rectangle with an image fill, at its natural size unless that would not fit in the view, inside the frame it lands on. Any shape's fill can be an image: Fill, Fit, Crop (choose the part shown) and Tile (choose the tile size), with opacity; the image can be replaced without touching the layer. A cropped image can be positioned on the canvas: "Drag the image to position it" under the crop numbers, then drag on the layer and the image moves inside it while the layer stays put, stopping at the image's edges (the layer's handles still resize it; Escape or "Done positioning" ends it). Every image has Exposure, Contrast and Saturation, each from -100 to 100, which change how it is drawn and never the stored image. Image bytes are stored once per device by content hash, and "Save a copy to disk" bundles them into the file, checked against their hashes when the file is imported.
- **Constraints (Phase 2).** A layer directly inside a frame can keep to the left, right or centre, stretch between both edges, or scale, and the same vertically. Resizing the frame — by its handles, in the properties panel, or as part of a larger resize — moves and resizes its children accordingly, in the same undo step; nested frames and groups pass it on.
- **Layout grids (Phase 2).** Frames can carry any number of uniform grids, columns and rows (count, gutter, margin or offset, stretched or aligned with a fixed size, colour and opacity). They are drawn over the design as guides, never into it; layers snap to their lines; View → Show layout grids (Shift+G) hides and shows them all.
- **Rulers and guides (Phase 2).** View → Rulers and guides (Shift+R) shows rulers along the top and left with page coordinates that follow pan and zoom, and marks the selection's extent on them. Drag out of a ruler to make a guide, drag a guide to move it, drag it back onto its ruler to remove it, or "Remove all" on the page's properties. Layers snap to guides. Guides are stored per page and, like layout grids, are never part of the design. Whether rulers are shown is remembered on this device. A guide let go over a frame is that frame's: it is a line across the frame only, at a position in the frame's own space, so it moves with the frame, and the layers in the frame snap to it. Dragged out of the frame it becomes the page's, and the other way round; a selected frame's properties show how many it has, with "Remove all".
- **Vector layers (Phase 3, first part).** Object → Flatten to vector (Ctrl+E) turns the selected rectangles, ellipses, lines, polygons and stars into a vector layer: one shape is converted where it is, several become a single vector that holds all their outlines, looks like the bottom-most of them and replaces them (shapes inside selected groups included). A vector is drawn with fills, gradients, images, strokes (all caps, joins, dashes; inside and outside only when it is closed), effects and blend modes like any other shape; it is selected by what it paints (a hole is not part of it); resizing it scales its curves, flipping it mirrors them, and its box always fits its curves. A fill can cover everything inside the outlines or treat a shape inside a shape as a hole (the "Fill covers" setting).
- **Boolean groups (Phase 3).** Object → Union (Ctrl+Alt+U), Subtract (Ctrl+Alt+S), Intersect (Ctrl+Alt+I) and Exclude (Ctrl+Alt+X), also as buttons in the properties panel, put two or more selected shapes, vectors, groups or boolean groups into a boolean group that shows: everything any of them covers; the bottom-most with the others taken out; what all of them share; or what an odd number of them cover. The shapes stay inside the group (listed under it in the layers panel; double-click to reach one on the canvas) and can be moved, resized, restyled, hidden, deleted or added to, and the result follows. The group's operation can be changed in the properties panel. The group is painted as one shape with the look of the bottom-most shape, and can be given its own fills, strokes and effects. Curves stay curves, cut exactly where outlines cross; holes come out as holes. Ungroup releases the shapes; Flatten turns the group into an ordinary vector of its result. Nothing happens when nothing would be left (an intersection of shapes that do not overlap).
- **Arcs (Phase 3).** An ellipse's properties have Start, Sweep and Ratio. A sweep of less than 360° leaves a slice starting at Start (degrees clockwise from three o'clock); a ratio above 0 cuts the middle out, which makes a ring, or with a sweep a piece of a ring. The slice or ring is what is painted, stroked, shadowed, selected (the hole of a ring is not part of it), flattened and used in boolean operations; the layer's size stays that of the whole ellipse. A selected ellipse shows round handles on the canvas: one at three o'clock that sweeps the arc, and once it is an arc one for its start (which leaves the end where it is) and one in the middle that opens the hole; Shift keeps angles to 15° steps.
- **Arrowheads (Phase 3).** The Stroke section of a line or a vector has Start arrow and End arrow: none, line arrow, triangle, circle or diamond. Heads are sized from the stroke weight, painted with the stroke's colour or gradient, stay solid on a dashed stroke, and are cast in drop shadows. On a vector they appear at the loose ends of its open paths. Flattening a line keeps them.
- **Outline stroke (Phase 3).** Object → Outline stroke (Ctrl+Shift+O) turns the stroke of each selected shape, line, vector or boolean group into a vector layer filled with what the stroke was painted with. It covers what the stroke covered: its width, inside / outside / centre position, ends, corners (sharp ones cut off at the same point the stroke's are), dashes and arrowheads. A layer that also has a fill keeps it and gets the stroke as a layer of its own on top; a layer that was only a stroke is replaced. Curved edges come out as curves, straight ones as straight lines.
- **Pen tool (Phase 3).** P, or the pen in the toolbar. Click to place points joined by straight lines; drag as you place a point to pull a handle out of it, so the path curves into the point and leaves along the drag. Click the first point (or any other point) to close the path or make a branch; click on a segment to put a point there. Shift keeps to 45° steps; points land on whole pixels and snap to nearby layers. A new path becomes a layer with its second point, inside the frame it starts over. Escape ends the path being drawn (the next click starts another in the same layer), Escape again puts the pen down, Enter finishes. Each point is one undo step, and after an undo the pen carries on from the end of the path. While a vector's points are open, clicking an end of a path picks it up again.
- **Pencil tool (Phase 3).** Shift+P, or the pencil in the toolbar. Drag to draw freehand; when the pencil is lifted the stroke is turned into a few smooth Bézier curves that stay within 2.5 screen pixels of what was drawn (so zooming in keeps more detail). A stroke that ends within 8 pixels of where it began is closed into a shape. Each stroke is its own vector layer with round ends, in the frame it starts over, and one undo step; the pencil stays selected for the next stroke. The result is an ordinary vector: its points can be edited like any other.
- **Editing points (Phase 3).** Double-click a vector, press Enter, or use "Edit points" in the properties panel or Object menu. Points are drawn as squares; click, Shift-click or drag a box to select them; Ctrl+A selects all. Drag points (or a segment) to move them, with the arrow keys nudging the selected ones; drag the handles of a selected point to reshape its curves, where the two handles of a smooth point turn together and Alt moves one alone; Ctrl-click switches a point between corner and smooth, Ctrl-drag pulls handles out of it. Delete removes the selected points and closes the path over the gap; Ctrl+J joins two selected points. The properties panel shows how many points are selected, the selected point's X and Y for typing, and Corner / Smooth / Join / Delete. Escape clears the point selection and then leaves point editing; Enter or a double-click away from the path also leaves it. The layer's box follows its curves throughout.
- **Masks (Phase 2).** Object → Use as mask (Ctrl+Alt+M), or "Mask the layers above" in the Layer section of the properties panel. A mask is not painted; the layers above it in its parent show only where it would have painted and only as strongly, so a half-transparent or gradient mask fades them. With several layers selected, the command groups them and makes the bottom one the mask. A hidden mask masks nothing. Masked layers can be clicked only where they show. The layers panel marks a mask with its own icon.
- **Colour picker (Phase 2).** Every colour swatch opens the application's own picker: a square for saturation and brightness, a strip for hue, the colour as HEX, as red / green / blue and as hue / saturation / lightness, and a dropper that takes a colour from anywhere on screen. Dragging previews on the canvas and is one undo step when released; the square and the strip also work from the keyboard. Escape or a press anywhere else closes it.
- **Gradient handles (Phase 2).** Each gradient in the properties panel has a button that shows its two handles on the canvas: where it starts (or its centre) and where it ends (or how far it reaches). Dragging one turns, moves or stretches the gradient, also outside the layer; Shift keeps its direction to 15° steps. Escape, deselecting or picking up a drawing tool puts the handles away.
- **Smaller things closed on 2026-11-16.** A rounded rectangle is selected by its rounded outline. While editing points, double-clicking a segment adds a point there, and "Cut" (properties panel, Object menu) cuts the path open at the selected points. The properties panel has buttons for the four boolean operations and Flatten. View → Snap to pixel grid (Ctrl+Alt+') switches whole-pixel snapping off and on for moving, resizing, drawing and the pen, and is remembered on this device. Deleting a file also deletes the images that no remaining file lists.
- **Side panels and theme (housekeeping, 2026-11-16).** The edge of each side panel that faces the canvas can be dragged to make the panel between 180 and 480 wide, moved with the arrow keys when it has the focus (Shift for bigger steps, Home and End for the limits), and double-clicked to put it back. View → Light theme switches the application's colours; the rulers follow, a design's own colours (its page background included) do not. Widths and theme are remembered on this device and apply to the file browser too.
- **System clipboard (housekeeping).** Copy and Cut put the layers on the system clipboard as well as on the application's own, with the images they use made known and the layers' names as plain text. Ctrl+V pastes layers from the system clipboard, so they can be copied in one window and pasted in another, into another file; what arrives is checked as a file is when it is opened (and brought up to date if an older version copied it).
- **Frames with rounded corners (housekeeping).** A frame is selected, and when it clips shows its children, only inside its rounded outline.
- **Menus and shortcuts.** Main menu (File, Edit, View, Object, Arrange, Help), context menus and a shortcut reference, all generated from one command table, so a menu item and its shortcut cannot disagree.
- **Auto Layout (Phase 4).** Object → Add Auto Layout (Shift+A), or the + of the "Auto layout" section of a frame's properties. A selected frame starts laying out its children, and reads the direction, the spacing, the padding and the alignment off where they are, so nothing moves; any other selection is put into a new frame that lays it out (a single text becomes the start of a button). Remove Auto Layout (Alt+Shift+A, or the − of the section) leaves everything where the layout put it. A frame's layout has: a direction (horizontal or vertical) and whether it wraps (a row carries on in further rows beneath it when it runs out of width, a column in further columns beside it when it runs out of height; the columns break again as the frame's height changes), the gap between items (a number, or Auto, typed into the gap field or switched on with the button beside it: the items are then spread from edge to edge and the gaps are whatever is left over. Auto is the same setting as the alignment "space between", and the panel shows the two in step: either one chosen shows as the other, the field says "Auto" while it is on, and a number typed there is a fixed gap again), padding (one value for left and right and one for top and bottom, or each side separately), alignment along the direction (start, centre, end, or "space between", which spreads the items from edge to edge) and across it (start, centre, end, or "Stretch", which makes every item as tall as a row, or as wide as a column, has room, whatever the item's own sizing that way; the panel says so on the frame and on each stretched item, whose own setting is shown but cannot be changed while it is not in use), for a layout that wraps the gap between its lines (which takes Auto in the same way) and whether the lines are packed together or spread out, and "Reverse order". The layers panel shows which way a frame with a layout runs. The order of a frame's children in the layout is their order in the stack.
- **Sizing in a layout (Phase 4).** The "Resizing" section, shown for frames with a layout, for text and for layers inside a layout: width and height are each Fixed, Hug contents (frames with a layout, and text) or Fill container (layers a layout places). A frame that hugs is exactly as big as its children, the spacing and the padding, and follows them: typing in a label, or adding, removing, hiding or resizing a child, resizes the frame and every frame round it in the same undo step. A child that fills takes the room that is left, shares it with the others that fill, and follows the frame when the frame is resized, whether by its handles, in the panel, or by its own constraints inside an ordinary frame. Minimum and maximum width and height limit what the layout gives. "Ignore auto layout" takes a child out of the flow: it stays where it is put, takes up no room, and follows its constraints when the frame changes size. What goes with a choice is done with it: a frame that hugged keeps its size when a child is told to fill it, a child that filled keeps its size when its frame is told to hug, and a text's own sizing mode is set to match. A size dragged out with a handle or typed in stands: the layer becomes fixed in that direction.
- **Components and instances (Phase 5, first part).** Object → Create component (Ctrl+Alt+K) makes the selected frame a component, or puts the selection into a new frame that is one. "Create instance" in the component's properties, or the + beside a component in the Components list of the left sidebar, places an instance: a frame that shows the component somewhere else and follows it. Whatever is changed in the component (a fill, a text, a layer added, removed or moved, its layout) reaches every instance in the same undo step. In an instance, a click picks the instance as a whole and a double-click a layer inside it; what that layer shows (its fill, stroke, effects, text, type, whether it is visible) can be changed there and is kept for that instance as an override, also when the component changes the same thing later. Where a layer of an instance is and how big belong to the component: such a layer cannot be dragged, its X and Y cannot be typed, and deleted it comes back. An instance can be resized (what is in it follows the component's constraints or Auto Layout), reset to its component, made to show another component (overrides are kept where the new one has a layer of the same name), or detached into an ordinary frame; "Go to component" selects its component. Components can hold instances of other components, and what is changed inside those is kept at each level. Deleting a component detaches its instances. The Components list shows the file's components (a slash in a name files it under a heading), finds them by name or description, and goes to one when it is clicked. In the layers panel a component and an instance have their own icons.
- **Figma `.fig` files (Phase 7, the owner's requirement).** "Import file…" in the file browser takes an `.opendesign` or a `.fig` file. A `.fig` file becomes a new file on this device; when some of it could not be brought over, a dialog lists what, with how many, before the file is opened. In the editor, File → "Save a copy to disk…" (Ctrl+Shift+S) now asks which format: OPEN DESIGN (`.opendesign`), or Figma (`.fig`), which says what the `.fig` file does not hold.
- **Export, import and Developer Mode (Phase 7).** *Export:* the Design tab ends with "Export" for the selected layers, or for the page when nothing is selected. "+" adds a way to export: a size ("2x", "512w", "300h"), a suffix, a format (PNG, JPG, SVG, PDF) and, under the arrow, its options (on the page's colour, JPG quality, ids in SVG, PDF as vectors or as a picture, PDF text as text or as pictures). "Export <name>" saves the file, or a ZIP archive when there are several. File → "Export…" (Ctrl+Shift+E) lists everything in the file that has export settings, to export together. Edit → "Copy as PNG" (Ctrl+Shift+C), "Copy as SVG", "Copy as CSS", also in the layer's context menu. *Import:* an SVG file that is placed or dropped comes in as a frame of editable layers (rectangles, ellipses, vectors, groups, clipped groups as frames, text, gradients), with a notice of anything left out; one that cannot be read that way is placed as a picture, as before. *Developer Mode:* the third tab of the right sidebar, "Inspect" (Shift+D). With a layer selected: its status (ready for development, completed), what it is in sections (layout, spacing in its parent, Auto Layout, typography, colours, borders, effects, component, variables and styles), its code as CSS, SwiftUI or Compose with "Copy", the component's code mapping, PNG and SVG assets, annotations, and links. With nothing selected: what is marked for development in the file and the annotations on the page. While the tab is open the canvas selects the layer under a click however deep, measures to the layer under the pointer, shows numbered pins for annotations and a tag on what is marked, and does not move or resize anything.
- **Prototyping (Phase 6).** The right sidebar has two tabs, Design and Prototype (Shift+E switches). With Prototype open and a layer selected: "Start a flow here" on a frame, with the flow's name; "Interactions", each with a trigger (on click or tap, on drag, while hovering, while pressing, after a delay, a key) and a list of actions (navigate to, open / swap / close overlay, scroll to, back, change to, set variable, conditional with "if it holds" and "otherwise" lists, type into variable), each with its destination and its transition (kind, direction, time, wait, easing, custom curve); "Scrolling" (which way a frame scrolls; whether a layer scrolls, is fixed or sticky); "As an overlay" (position, closing on a click outside, background). With nothing selected: the device and the page's flows. On the canvas, connections are drawn as arrows (dashed for anything but "navigate to"), flows are marked at their starting frame, and the selected layer has a round handle beside its right edge: dragging it to a frame makes "on click, navigate to" that frame. "Present" (top bar, Ctrl+Alt+Enter, or beside a flow) plays the prototype at `#/proto/<file>/<frame>`: the viewer has the name of the screen, the flow, the device (drawn as a frame round the screen), the scale (fit, fit width, actual size), Back, Restart (R), "Copy link" and "Full screen", which hides the controls. A click that does nothing shows for a moment where a click does something.
- **Libraries (Phase 5, fourth part).** "Libraries…" in the File menu. "This file": what it would publish (components, styles, variables), whether it is published and at which version, whether it has changed since, and "Publish" / "Publish changes" / "Unpublish". "Available": the other published files on this device, each with "Add to this file". "Used in this file": the libraries added, their version, "Update" when the library was published again, and "Remove". A library's components appear in the Components list under the library's name and are inserted like the file's own; its styles and variables appear in the style and variable menus with the library's name after them. They cannot be changed in the file that uses them. When a file is opened and a library it uses has a newer version, a notice at the top says so.
- **Styles and variables (Phase 5, third part).** With a layer selected, the "Styles" section has a menu for each kind of style that fits it (fill, stroke, text, effect, grid): choose a style, "None" to detach, "New style from this layer", or "Update" a style to match the layer. The "Variables" section lists the properties bound to a variable and binds another ("Bind a property…", then the variable); on a frame it also has a menu for the mode of each collection that has more than one. With nothing selected, the panel lists the file's styles (rename, describe, delete; a single solid colour and a text style's font, size and weight are edited there) and has "Edit variables", a dialog with collections, modes (add, rename, remove) and a row for each variable: its name, its value in each mode or the variable it stands for, a description and what it is offered for. The page's mode is chosen under "Local variables". A change to a style or a variable changes every layer that uses it in the same undo step; changing a styled or bound property by hand detaches it.
- **Variants and component properties (Phase 5, second part).** "Combine as variants" (Object menu, or the button in a component's properties) puts the selected components into a component set, drawn with a dashed outline, in which each is a variant with a value for the set's variant properties. On the set: variant properties are renamed, added and removed, and "Add variant" adds a copy of the last variant under it; on a variant: its value for each property. An instance of a variant has a menu for each variant property, and choosing a value makes it show the variant that fits best, keeping what was changed in it. A component, or a set for all its variants, can define properties: Boolean (whether a layer shows), Text (what a text says) and Instance swap (which component an instance inside it shows). A layer of the component is bound to a property in its own "Component properties" section; an instance then has a switch, a text field or a menu for each, and for the properties of the instances inside it too, under their names. A property set on an instance holds when the component changes and when the instance changes variant; typing into a bound text of an instance, or hiding a bound layer, sets the property. Reset gives properties back to the component as well.
- **Layouts on the canvas (Phase 4).** Dragging a child inside its layout changes its place among the others: it takes the place the pointer is over (and is not dropped into a neighbour that is a frame). Dragged off the frame it leaves the layout and the others close up; a layer dropped onto a layout, and an image file dropped on one, takes the place it is dropped at (a pasted image goes to the middle of the view, and takes its place in a layout if there is one under that point). Shapes and text drawn into a layout take the place they are drawn over. The arrow keys move a child one place along its layout. A child that a layout places has no X and Y to type in (the fields are disabled) and no constraints.

## Known limitations and rough edges

- Masks use the mask's painted opacity only (no luminance masks). A mask cannot be clicked on the canvas; select it in the layers panel. Where the renderer cannot composite (it always can in the browser), a mask clips by its outline.
- Rulers and guides: a guide cannot be typed in as a number and cannot be locked. A frame that is turned, or inside something turned, does not take or show guides (the ones it has are kept). When a frame is made smaller, a guide left outside it is kept but not shown. Rulers are off until switched on.
- Constraints use a layer's unrotated box, so a rotated child follows its frame only approximately. Minimum and maximum sizes are kept by Auto Layout only, not when a layer follows constraints, and there is no "fixed position when scrolling".
- `.fig` files: see ".fig files: what is converted, and what is not verified" below.
- Export: a PDF's text is written in Helvetica, Times or Courier, whichever is nearest the design's font, with each character placed where the design's own font puts it, so lines keep their length but letters look like the stand-in's and may sit unevenly; "text as pictures" keeps the exact look and loses selectable text. A vector PDF has no shadows or blurs, applies a mask only by its outline, writes angular and diamond gradients as radial ones and partly transparent gradient stops as solid; "as a picture" keeps all of that. SVG has no angular or diamond gradient (written as radial), no background blur, no shadow spread, and no image adjustments; text in an SVG is real text, so it needs the font where it is opened. A picture is at most 16384 pixels a side. "Copy as PNG" copies the first selected layer. Several files are saved as one uncompressed ZIP archive, through the browser's download, not to a folder of the designer's choosing. There is no export of a prototype or of code beyond what Developer Mode shows.
- Import: an SVG's clipping paths (other than an upright rectangle round a group, which becomes a frame), masks, filters, patterns and embedded pictures are left out, and said to be; `<style>` rules are read for classes, IDs and element names only; a text element becomes one text layer in the style of its first words; shapes under a rotation, skew or uneven scale come in as vector outlines, not as rectangles or ellipses. PDF files cannot be imported. A GIF is placed as its first frame.
- Developer Mode: the Swift and Kotlin code is a starting point for one layer (the nearest view and its modifiers), not a screen; CSS is for one layer at a time and names images by their file name. Measurements are to the layer under the pointer, from the selection; there is no ruler tool of its own. There is no comparing of versions, no list of what changed since a status was set, and no editor integration.
- Prototyping: a prototype link opens only in the browser that holds the file, and there are no prototype permissions: both need a server. An overlay sits at one of seven places on the screen, not at a place relative to the layer that opened it, so a dropdown has to be designed at its place. "While hovering" and "while pressing" undo what they did when they end; an interaction for "mouse leave" or "mouse up" on its own does not exist. Keys are single keys without modifiers. "Set variable" sets the value in every mode. "Type into variable" has no caret or selection: typing adds to the end and Backspace removes from it. Smart Animate matches layers by name and type among siblings; it animates position, size, rotation, opacity, corner radius, stroke weight, font size and solid colours, and switches everything else (gradients, effects, text) at the start. A transition that is running is not interrupted smoothly by the next one: the next starts from where the first would have ended. Scrolling has no momentum and shows no scrollbars. Sticky layers stick to the top only. Device frames are a plain bezel round the screen. There is no video, sound, or opening of links, and the Design tab's panel does not show a layer's interactions.
- Libraries: a library is a published file in the same local storage of the same browser; there is no sharing between people or devices until there is a server (Phase 6 onwards), other than sending the `.opendesign` file, which a using file does not need: it holds a copy of what it uses. Adding a library copies everything it published, not only what is then used. A file is told about a newer version when it is opened and when the Libraries dialog is open, not while it stays open otherwise, and "Update" takes the whole new version: there is no choosing item by item and no list of what changed. A library's components cannot be opened from the file that uses them ("Go to component" is off for them): the library file is opened from the file browser. A library that uses another library publishes that one's components and all its styles and variables along with its own. Publishing writes the whole snapshot into the library's file, which grows by about the size of its components.
- Styles and variables: a colour style with more than one paint or a gradient, and effect and grid styles, are edited by changing a layer and choosing "Update" in its style menu, not in the list of styles. A text style sets a whole text layer, not a part of one, and does not hold alignment. Variables bind to the colour of a solid paint (not to gradient stops, effects or layout grids), and number variables have no units. A corner-radius variable sets all four corners. Collections and variables are listed by name and cannot be reordered or grouped into folders (a name may contain "/", which is shown as it is). Styles and variables cannot be copied between files with copy and paste: a layer pasted into another file keeps the look and loses the references. There is no import or export of token files (JSON) yet.
- Variants and properties: a set does not lay its variants out (they are placed by hand, and "Add variant" only makes room downwards), and nothing stops two variants having the same values (an instance then shows the first). A component property has no default of its own: it starts as what the bound layers have in the component. Properties cannot be reordered. A text property replaces the whole text of a layer and its styled parts stay where they were. A value an instance has for a property is kept when the property is unbound from a layer, and has no effect until something is bound again.
- Components: the layout settings of a layer inside an instance, and its place and size, cannot be overridden (only what it shows can). A layer of an instance can still be resized by its handles, which holds only until the component next changes that layer's size. Layers cannot be added to an instance, and nothing can be dropped into one. An override of a text's style on part of the text is kept as the whole list of styled parts, so a later change to the component's styled parts does not reach that instance. Swapping keeps overrides by the type and name of layers, so a renamed layer loses them. There is no way yet to push an instance's overrides back to its component. Instances are in step after every change through the editor; a file edited by hand so that they are not is put right at the first change, not when it is opened. Every change walks all instances of the document.
- Auto Layout: A frame that stretches its children cannot hug across its layout (it keeps the size it has), and Stretch does not reach a rotated child, a line's height, or text that fits itself to its content that way. A stretched child cannot be resized across the layout by its handles: the layout puts it back. There is no alignment for one child alone or along the baseline of text. Spacing is one number per frame, or Auto; items can be spread from edge to edge but not with space round each ("space around"). A frame whose spacing is Auto cannot hug along its layout, nor across it while the lines of a layout that wraps are spread out: it keeps the size it has. A child being dragged inside its layout does not follow the pointer: it jumps to the place it will take. To put a child into a neighbouring frame, drag it out of the layout first or use the layers panel. Nothing on the canvas shows padding or spacing, and they cannot be dragged there. Strokes take up no room in a layout. A rotated child takes the room of the box round it and cannot fill. A frame cannot hug along an axis on which a child fills it: telling the child to fill makes the frame fixed. A frame whose children have all gone keeps its size while it still says "Hug". A column that wraps and is given its height by the frame it is in (it fills, or is stretched) is laid out again until its columns suit that height, in four runs at most; if frames nested that way still disagree after that, the last result stands. A child that fills the width of a wrapping column and whose height depends on its width (text that wraps) is put into columns by the height it has at the frame's whole inner width, so such a column can come out taller or shorter than the frame. Sizes are not forced to whole pixels: three children that fill 100 are 33.333 each. When a file is opened its layout is not worked out again (the stored result is used, as §5.7 of DOCUMENT_SCHEMA.md says); stored boxes that disagree with the layout's settings, which only editing a file by hand can produce, are put right at the first change. The layout pass, like the other passes that run after each change, walks the whole document; fine at thousands of layers, untested beyond.
- Images: dragging positions the part of a cropped image that shows but does not change how much of it shows (the crop's width and height are typed), and there are no crop handles on the canvas. The adjustments are exposure, contrast and saturation only (no temperature, tint, highlights or shadows), and they use the canvas's `filter`, which Chrome, Edge and Firefox have; a browser without it draws the image unadjusted (only Edge is tested). No PDF import. An animated GIF shows its first frame. SVG is placed as a picture, not converted into editable vector layers. Image fills are not drawn on strokes or text. An image is removed from the browser's storage when the last file that lists it is deleted; an image that was placed and then removed from a file stays until that file is deleted.
- Gradients: the handles on the canvas move a gradient's start and end; its colour stops are edited in the properties panel only. On text and strokes, radial and angular gradients are circular rather than stretched to the box, and diamond falls back to radial.
- Shadow spread works on rectangles, ellipses and frames only. Inner shadows are not drawn on text or groups. A drop shadow shows through a translucent fill. Background blur does not see through a group that is itself being composited (one with a blend mode, blur or partial opacity).
- The colour picker has no saved swatches or colour styles, and no opacity slider of its own (opacity is the field beside each colour). The dropper is offered only where the browser has one (Chrome and Edge do) and is not covered by a test, because a test cannot operate it.
- Snapping covers other layers, frame edges and centres, layout grids, ruler guides and even spacing. Even spacing is offered while moving only (not while resizing or drawing) and against the layers in the same container; the gap to a frame's own edge is not matched (its centre line is). On the pixel grid a halfway place that falls between pixels is not offered. Distances are those between bounding boxes along the page axes, so for rotated layers they are the boxes' and not the shapes'. Nothing snaps inside a rotated frame. The numbers of distances are drawn on the canvas only, so a screen reader does not get them.
- Text, parts in their own style: a part can have its own solid colour but not its own gradient, image or several fills, and not its own line height, case or alignment (those belong to the layer). A colour from the picker is applied when the picker's drag ends, not while dragging. With only a caret in the text, a setting goes to the whole layer; there is no "style for what I type next". Changing a setting in the panel while a text is open is its own undo step, and starts the typing history (Ctrl+Z inside the text) afresh. Text typed with an input method (Chinese, Japanese, Korean and the like) is taken into the document when the composition ends; this path is written but **has not been tested**, as no test can drive an input method. The mark on the selected part while the panel has the keyboard needs the browser's highlight feature (Chrome and Edge have it); without it the part is still selected but not marked.
- Text, lists and justified lines: a list is the whole layer (no nested levels, no list for some paragraphs only), and its markers stay at the left when the text is centred or right-aligned. While a justified text is open for typing, the browser spreads its lines in its own way, which can differ slightly from how the canvas draws them. No text on a path. Only Inter is bundled: any other family in the font menu is the machine's own, and a file that uses a family another machine does not have shows a fallback there. Text made before the font was bundled keeps the family it had (Arial). The fonts for Latin text (eighteen files, about 450 KB in all) are fetched before a file is shown, with a four-second limit after which the file opens anyway and is measured again when they arrive. The build carries each face in two formats (about 4 MB of font files), of which a browser fetches only what it needs. Text strokes are always centred on the outline.
- While text is being edited, the in-place editor ignores vertical alignment and may sit a fraction of a pixel off the painted text; with a fixed line height and text of several sizes on one line, its lines can be taller than the canvas draws them.
- Flip and mirroring: an angular gradient keeps turning the same way after a flip, and a frame's layout grids stay as they are. Text that is mirrored is edited mirrored. A resize from the centre (Alt) has no fixed edge and never mirrors. A line's two ends are dragged separately, so a line is not mirrored by resizing.
- Arcs: the handles on the canvas appear only on a single selected ellipse that is at least 48 pixels across on screen. Shadow spread does not apply to a slice or a ring.
- Arrowheads: a vector has one start and one end setting for all its open paths, not one per end point. Heads are not included in hit testing or in the layer's size, and there is no size setting apart from the stroke weight. A stroke's width cannot vary along its length.
- Outline stroke: curved edges are fitted to within a twentieth of a pixel of the stroke's true edge, not exactly on it. Text and frames cannot have their strokes outlined. A stroke painted with several paints becomes one shape filled with all of them. The outline of a very intricate path (thousands of points) can take a noticeable moment.
- Boolean groups: text or a frame moved into one is neither combined nor painted while it is there. A shape of a group that does not show (the part taken out by Subtract) can be selected from the layers panel only. Outlines that only touch, or curved outlines that run along each other (two identical circles), may give a wrong result; straight edges that coincide are handled. Results are worked out to about a hundredth of a pixel, so slivers thinner than that are lost. Strokes are not part of a shape: only its outline (what its fill covers) takes part. Text cannot take part.
- Pencil: sharp corners in a stroke come out slightly rounded, because the fitted curves are joined smoothly. How much a stroke is smoothed is fixed (no setting), and pen pressure is not used.
- Pen and points: segments that cross each other are not split where they cross. Handles are shown for the selected points only. The pen starts a new layer unless a vector's points are open. The preview line that follows the pen is not covered by a pixel test. Undo does not restore which points were selected. A new path's hairline black stroke is hard to see on the default dark page until it is given a fill or another colour.
- Vectors: a layer's position is kept to a thousandth of a pixel, so each time its box is refitted its curves can shift by less than that.
- Vectors: regions of a branching network are found on the assumption that its segments do not cross each other; where they do, the fill can be wrong. Stroke joins are not drawn where three or more segments meet. Shadow spread does not apply. An inner shadow on a vector whose outlines overlap under the non-zero rule is cast inside the overlap too. Text cannot be flattened to a vector.
- Alt+D (align right) is also the browser's "focus address bar" shortcut and the browser may take it first; the button and the menu item always work.
- Resizing a multi-selection that contains rotated layers scales their boxes approximately; it cannot skew.
- Clipboard: layers travel between windows of the same browser. Another browser will not see them (browsers keep a page's own clipboard formats to themselves), and no other application can read them except as the layers' names. Paste from a menu uses the application's own clipboard, which holds only what was copied in that window: pasting from another window needs Ctrl+V. Images used by pasted layers are found only if this browser profile has them (it has, for anything placed in it). Images on the system clipboard can be pasted in.
- The layers panel makes only the rows in view, but the list of rows itself is rebuilt from the page on every change, and culling on the canvas is a linear walk (no spatial index). Fine at thousands of layers, untested beyond that. A drag in the layers panel onto a row that is not in view relies on the browser scrolling the list. There is no WebGL backend.
- Keyboard shortcuts match physical key positions, so letter shortcuts follow a QWERTY layout.
- Theme: the file browser follows the theme but has no switch of its own (it is in the editor's View menu). A new file's page is dark in both themes, because the page colour belongs to the design. The colours drawn over the canvas (selection, guides, frame names) are the same in both themes.
- Files live in the browser profile that created them, per address (`localhost:5173`). Clearing site data deletes them; use "Save a copy to disk" for anything that matters.
- Licence: the project is under the MIT licence (`LICENSE`, chosen by the owner on 2026-11-16); the bundled Inter font keeps its own, the SIL Open Font License 1.1 (`THIRD_PARTY_NOTICES.md`). The copyright line names "The OPEN DESIGN contributors"; it should be changed if a person or an organisation is to be named instead.

**Phase 4 (Auto Layout): what is still open.** Every item of the specification's Phase 4 list (horizontal and vertical Auto Layout, padding, spacing, alignment, wrapping, hug contents, fill container, fixed dimensions, constraints, responsive resizing, nested layouts) and of its Auto Layout section has a tested implementation; none is recorded as not done. What stops short of what a designer may expect is the "Auto Layout" entry under "Known limitations". Three items of the Auto Layout section that were first built as a reading of the list are now there under their own names: "Stretch" as an alignment across the layout (schema 16), "Automatic spacing" as Auto in the gap field, and "Wrapping" for columns as well as rows (schema 17). "Child alignment" is the layout's alignment of its children; there is no alignment for one child alone, and none is in the list. Of what stops short, the ones most worth doing next: padding and spacing shown and dragged on the canvas, and a dragged child that follows the pointer.

**Phase 5 (Components and design systems): what is still open.** Every item of the specification's Phase 5 list (components, instances, component sets, variants, component properties, instance overrides, libraries, styles, variables, modes, design tokens) has a tested implementation, and the seven acceptance tests of §33 for components (create component, create instance, change master component, preserve instance overrides, swap instance, change variant, reset overrides) pass in unit tests and in the browser. None is recorded as not done. What stops short of what a designer may expect is in the "Libraries", "Styles and variables", "Variants and properties" and "Components" entries under "Known limitations"; the largest are that libraries are local to one browser until there is a server, and that styles and variables do not travel with copy and paste between files. 

**Phase 6 (Prototyping): what is still open.** Every item of the specification's Phase 6 list (prototype connections, triggers, actions, transitions, Smart Animate, overlays, scroll behaviour, interactive components, variables, conditional logic, presentation mode) has a tested implementation, and the eight acceptance tests of §33 for prototypes (create connection, trigger click, navigate between frames, open overlay, close overlay, run transition, change component state, execute conditional action) pass. Two items of the specification's prototyping section are not built because they need a server: prototype permissions, and prototype links that work for someone else (the link works in the browser that holds the file). The acceptance criterion says "build and share": building is done; sharing waits for Phase 8's server or for exporting the file. Phase 7 followed it; its open part is the `.fig` work below.

**An owner's requirement for Phase 7, added on 2026-11-16 and not in the specification's list:** Figma's `.fig` files. In the owner's words: "it should be compatile with .fig figma files too i should be able to open,view and edit them completely". So Phase 7's import work includes opening a `.fig` file from disk as an OPEN DESIGN document that can be viewed and edited like any other. What whoever builds it must know and report honestly: `.fig` is Figma's own binary format with no published specification, and it changes without notice, so it has to be read from what can be worked out about the file itself, with no Figma account, server or library (the specification's rule that the application does not depend on Figma still holds: this is an import, and the native format stays `.opendesign`). "Completely" can therefore only be promised feature by feature: each kind of layer and property is either converted and tested against a real `.fig` file the owner supplies, or listed as not converted. It also depends on Phases 5 and 6, since a `.fig` file holds components, variables and prototype connections that have nowhere to go until those exist. 

**Added by the owner later the same day:** saving as `.fig` as well. In the owner's words: "it should also have an option to save as a fig file or open design 2 options", and, on the point above that completeness can only be reached feature by feature, "compelyely shpould work". So the target is not a partial converter: "Save a copy to disk" offers two formats, `.opendesign` and `.fig`; a `.fig` file opens with everything in it editable; and a file saved as `.fig` opens in Figma. The work is finished only when no kind of layer or property is left on the "not converted" list, and until then that list is shown to the owner as what is still open, never described as done. A `.fig` file written by this application has to be checked by opening it in Figma itself, which no test here can do: the owner has to do that check, or it is reported as not verified.

**.fig files: what is converted, and what is verified (2026-11-16).** Built: `src/core/fig/` (`zstd.ts`, a Zstandard decoder; `kiwi.ts`, Figma's binary encoding; `fig.ts`, reading and writing; `sha1.ts`), `src/persistence/fig.ts`, the import in the file browser and the format choice in "Save a copy to disk".
*Checked against a real file.* The owner supplied a real Figma file, "EXPATS final.fig" (11 MB, format version 106, 7,699 nodes, 289 images), kept in `.tools/fig-samples/` (ignored by git: it is the owner's design; `src/figsample.test.ts` and `e2e/figsample.spec.ts` run only where it is). The format was as assumed (an archive with `canvas.fig` and `images/` named by SHA-1; "fig-kiwi", a deflated schema and a Zstandard-compressed message; the field names of `NodeChange`, `Paint`, `Effect`, `SymbolData`, `TextData`, `VectorData`), and the Zstandard decoder read its 900 KB message. All 7,659 of its layers come through, with every count matching Figma's: 2,327 texts, 373 components, 19 component sets, 1,118 instances, 419 vectors, 1,320 Auto Layout frames, 351 prototype interactions, 12 flows, 12 text styles, 22 variables in one collection, 289 images; it needs no repair, and saved as `.fig` and read again it has every layer. Seen in the browser, the design system page draws its swatches, flags, tickets, globes, navigation and buttons. What the file showed that had been missed and is now converted: sections (as frames), hug and fill in Auto Layout, wrapping and the spacing between lines, absolute positioning in a layout, constraints, scroll behaviour, variants' values (from their names), component properties (boolean, text, instance swap) with the layers bound to them and instances' values, changes inside instances (fills, strokes, visibility, opacity, text, font, swapped components, effects, prototype links), parts of text in a style of their own, shared text, colour and effect styles and the layers that use them, variables (colour, number, string, boolean; collections, modes, aliases, scopes) and colours bound to them, prototype interactions (click, hover, press, after a delay, drag; navigate, overlays, back, close, scroll to, change to; transitions with direction, duration and easing) and flows.
*Taken further on 2026-11-16 and 17, at the owner's request ("all nodes should work for all types of fig files … it should not miss anything like auto layout, constraints, variables, styles, variants"), and after the owner's screenshots of the imported file showed icons on top of their labels.* Now converted as well: **every kind of node** (kinds this application has no layer for, such as FigJam's stickies, shapes with text, connectors, tables, code blocks, stamps and widgets, slices and kinds Figma adds later, are kept as the nearest thing: a frame round what they hold, a vector of the outline Figma keeps of them, or a box, with their text as a text layer in them; vectors whose points are missing are drawn from that outline); **flipped layers** (vectors exactly, text and pictures by their own flip, gradients turned over, and a flipped frame or group kept upright with what it holds turned over inside it, corners swapped to match); **strokes of a different weight on each side** (schema 24, drawn, exported and written back to `.fig`); **every change inside instances**: names, sizes, stroke weights and per-side strokes, being taken out of an Auto Layout flow, and changes inside instances that are inside instances, to any depth, with the values of inner instances' properties; **instances at a size of their own** have what is in them placed and sized by their constraints, as Figma does (this was the owner's overlapping icons: a 24 px icon placed at 13 px kept its 24 px lines, and the points of vectors in a resized instance also went back to the component's size after any edit, in the editor as well; both fixed); an instance scaled with Figma's scale tool (taken to be so when it is exactly in proportion to its component and its constraints would leave what it holds sticking out) has its contents scaled with it, strokes, corners, shadows and type included, kept as changes made in it; an instance swapped for another component takes that component's size where it had the old one's (in the editor too); **layout grids**, **grid styles**, **guides**, **export settings**, **minimum and maximum sizes**, **variables bound to** radius, stroke weight, spacing, padding, visibility, text, sizes, opacity, font size, letter spacing, line height and font family, **the mode chosen** on a layer, **scrolling**, **overlay settings**, **the prototype's device**, **Auto Layout rows aligned on the baseline of text** (schema 24: `BASELINE`, also in the Design panel as "Text baseline"), **bulleted and numbered lists**, **images kept inside the file**, **videos** (by their first frame), **key presses**, **"set variable"**, **conditions** (Figma's expressions written as this application's) and **links** (schema 24: `OPEN_LINK`, opened by the viewer in a new tab, `http`, `https` and `mailto` only). An independent review of the work (three reviewers, each finding checked by another) found fourteen faults, all fixed with tests: a flipped instance shown upside down (it cannot be shown mirrored here, so it is now shown unflipped and listed), a component's flip baked into every instance, flipped vectors' gradients, sides and arcs not turned over, a list in one paragraph making the whole text a list, quoted text in expressions, a nested instance stretched by its outer one sized from the wrong start; and in the editor itself, instances losing their own layout when everything was laid out again as fonts arrived, vectors stretched by Auto Layout keeping their old points, a swapped instance keeping the size of the one it replaced when swapped back, a deleted swap target leaving its layers behind, an instance's own per-side stroke not taken from its component, and per-side strokes left out of a layer's drawn bounds and shadow. Checking the real file afterwards found one more: weights for each side counted in a change inside an instance where Figma does not use them (they count only where the sides are independent).
*Still not converted, and listed when met* (the real file has none of these): flipped components and instances (shown unflipped: what is in an instance is drawn as its component has it), space between paragraphs and indents, a list in only some paragraphs of a text, links inside text, quotes and checklists, smoothed corners, masks by luminance or outline, linear burn and dodge (drawn as multiply and screen), overlays placed by hand or beside the layer that opened them, key presses with modifier keys, devices of a size of their own (the nearest of phone, tablet, desktop), flipped polygons and stars and the items of flipped Auto Layout frames, Auto Layout inside an instance scaled with the scale tool (its spacing and padding keep their sizes), instances of components from other files, image crops, spring easings, component properties other than boolean, text and instance swap, bindings of variables to other properties, prototype triggers other than click, hover, press, delay, drag and key, actions that change a variable's mode or play media, expressions Figma has that this application's do not, and paints and effects other than solid, gradient, image, video, shadows and blurs. Not written to `.fig`: overrides, component properties, styled parts of text, lists, Auto Layout sizing, layout grids, image crops and adjustments, prototype connections and flows, styles, variables, export settings.
*Not verified:* that a file written here opens in Figma (the owner is to try it), and any Figma file other than this one.
*Speed and memory, found with the real file:* bringing instances into step after a change copied and re-indexed the whole document once per instance (120 s to open this file). It now works in waves by depth and only on instances a change can reach; `setNodes` no longer copies the document when nothing differs; Auto Layout writes its changes once per pass; the `.fig` decoder skips Figma's derived data (measured glyphs, thumbnail hashes, undo history) without building it, and reads byte arrays without copying them; and the import's pass over resized instances works on small documents of one instance each, merged once. Measured on 2026-11-17 in Node with the approximate text measurer: opening the file takes 4.2 s (14,777 nodes with the layers of instances, about 230 MB of heap), moving a layer 0.2–0.25 s, and changing the component with the most instances (101) 0.13–0.17 s; it was 2.7 s per edit at the last commit.

Rules that have held so far and should keep holding:

- Every schema addition bumps `CURRENT_SCHEMA_VERSION`, adds a migration in `MIGRATIONS` (`src/core/document/serialize.ts`) and a test that opens a file of the previous version. The schema is at version 24.
- Every feature gets a unit test at the level of the real operation and, where it is visible, a browser test that reads the result back (panel values or canvas pixels).
- `DOCUMENT_SCHEMA.md` and this note are updated in the same commit as the change.
